## 行为

底部入口为「随刊 · 见闻 · 随行」。见闻默认全部城市，城市目录来自已发布地点，按城市过滤并分页；切换城市后丢弃旧分页请求。没有关注、分类、提问入口或「旅人分享」标题。时间显示为具体时分。

动态图片、标题、正文、地点打开同一个详情；详情含评论、回复、点赞、收藏。地点旁的「去随行」传递 `route_slug + fragment_id`，直接选中分享中的真实地点，不启动定位、不自动播放。已有另一条随行时，先由用户决定是否结束当前随行并前往。随行页的「留一则见闻」预选当前地点。

分享支持文字、图库照片、已发布地点和到访日期。草稿按账户保存到本地，照片复制到应用私有目录；退出账户清除草稿和照片。发布失败保留草稿及幂等键，成功清理。发布位置是选择的内容地点，不读取发布时 GPS。照片沿用后端规范化、去 EXIF 和鉴权访问。

## 接口与发布顺序

- `GET /api/v1/community-posts?city=&cursor=&limit=`：全城/指定城市动态，只有已发布景区的可见内容。
- `GET /api/v1/community-places`：可关联地点，带景区与城市信息。
- `POST /api/v1/community-places/:fragment/posts`：不要求先开启旅程；固定分享类别 `on_site`，multipart 照片、正文、幂等键和 `visited_on`。
- `PUT / DELETE /api/v1/community-posts/:id/saved`：账户收藏状态。
- 复用原有详情、图片、点赞、评论与回复接口；保留旧旅程节点权限检查。举报过的内容不会出现在本人的全城动态中。

部署时先运行后端迁移 `alembic upgrade head`（新版本 `20261009_0018`，增加可空的到访日期），发布新后端，再发布客户端。此次工作提交代码和截图，未部署线上服务、未发布手机安装包。无内容时显示空态，不插入设计稿中的示例动态。
