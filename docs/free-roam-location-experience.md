# 自由漫游与定位触发实现说明

## 范围

本次实现只调整正式旅程中的真实定位体验：用户可以按任意空间顺序接近节点，客户端保留原节点轨道作为唯一主入口，触发过的内容可以回看和回听，未完成旅程也会出现在足迹中并可继续。推荐路线、地图导航、城市坐标识别、连续轨迹保存和模拟触发均不属于本次范围。

## 发布与触发规则审计

现有内容模型没有独立的“故事点发布状态”。一个故事点可被新的真实定位请求触发，采用以下既有组合：

- 故事点属于当前旅程的稳定故事弧和路线清单；
- 路线 `content_status` 为 `published`，且 `published_at` 非空；
- 故事点具有完整的 WGS-84 触发区域和可用旁白投影；
- 旅程归当前登录或游客身份所有；
- 同一幂等键重复提交返回原结果。

路线撤回后拒绝新的真实定位触发，但所有已经写入旅程账本的故事点仍可由原所有者读取和回听。故事点的 `review_state`、触发区域 `audit_state` 和故事弧现场审核状态继续用于生产就绪提示；它们没有被额外设成运行时门禁，以免改变当前已发布路线的兼容行为。

后台现有内容图编辑器及 JSON 内容包已经支持故事点坐标、进入/离开半径、精度阈值、稳定采样数、采样窗口、冷却时间、坐标来源、任意体验标签、旁白和发布流程，因此本次没有管理端、数据库迁移或固定标签枚举改动。

## 客户端行为

- 每次实时位置更新只保留最新一个内存样本并计算各故事点距离；不保存计算距离或行走轨迹，也不把定位写入普通 API 请求或运行日志。符合触发条件的单个证据样本会发送给既有触发接口；若触发请求离线失败，既有私有 outbox 只在重试期间暂存该请求样本，成功同步后立即删除，不形成连续轨迹。
- 节点轨道严格按后台返回的实际节点数量渲染，不假定固定五个；节点较密时自适应尺寸和间距，单行无法安全容纳时允许横向滚动，仍保留至少 44dp 点击区域。
- 点击任意节点后，轨道下方先展示该节点的后台安全预告、主题、预计时长、已听状态和临时接近状态，现有音频卡片位于该文案区下方。未触发节点的点击只改变界面选中态，不触发、不解锁、不播放、不写进度。
- 有当前位置时只在所选节点详情中展示临时距离和接近状态；没有当前位置时保留后台节点顺序且不显示距离。距离排序派生数据不再替换原节点入口。
- 每个故事点独立使用自己的进入/离开半径、精度、稳定采样和冷却策略。依赖关系只用于最终故事因果重构，不限制空间触发。
- 未触发点只能查看安全预告；已触发、播放中、中断、待留念、已听或已重构点均可回看文字稿和回听。
- 活跃旅程回听旧故事时继续监听真实定位。此时触发的新故事会排入同一播放器队列，回听结束后恢复现场播放，不重复触发或重复收集旧故事。
- 照片和观察提示继续是可选记录，不影响触发、回听、恢复或重构资格。
- 足迹列表使用同一份用户旅程集合，同时展示进行中和已完成项目；继续进行中的项目会加载服务端旅程上下文和账本，而不是重置到第一点。

## API 兼容与部署

故事点响应新增可选字段：

- `display_theme`：优先取后台任意体验标签的第一项，否则使用路线主题；
- `expected_duration_seconds`：当前内容模型未保存音频时长，服务端依据正式文字稿给出保守估时，最低 30 秒。

Flutter 将两项都按可选字段解析，旧服务端缺失字段时不伪造主题或时长。推荐按“服务端先发布、客户端后发布”的顺序部署。回滚客户端不会影响新增字段；回滚服务端时，新客户端仍可按旧字段运行，只是不展示主题或预计时长。撤回路线即可立即停止新的现场触发，同时保留既有用户进度。
