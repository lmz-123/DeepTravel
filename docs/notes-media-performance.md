# 见闻图片与列表加载（2026-10-11）

此次只处理图片分规格加载和列表懒加载两项最高优先级问题，保留见闻卡片布局。未添加磁盘缓存、CDN 直连或数据库查询优化，也没有改变详情返回时的刷新策略。

## 图片规格

`GET /api/v1/community-media/:id?variant=thumbnail|preview|full` 继续执行原有用户认证、见闻可见性和举报隐藏检查。

- `thumbnail`：最长边 240px，WebP quality 82，用于详情底部的小照片。
- `preview`：最长边 960px，WebP quality 85，用于列表和详情默认图片。
- `full` 或不传参数：原有清晰图，用于打开大图后的查看/缩放。新上传依旧遵循 `COMMUNITY_MEDIA_MAX_EDGE`（默认 1920px）、quality 88；PNG 转为 WebP，保留透明通道，不继续存储大体积 PNG。较小图片不放大。

新上传提前生成两种预览；旧文件第一次访问对应预览时按需补生成并持久化，后续复用。旧 OSS 文件、对象键、校验和和数据库记录不覆盖。第一次访问历史图片仍有读取源文件与编码的成本；此次没有对生产 OSS 执行批处理。

衍生图以原对象键加规格及版本后缀保存，不需要数据库迁移。删除见闻或回滚失败上传时同时清理衍生图。小图生成失败不会悄悄回退到大图。客户端图片 provider 的标识包含用户、图片 ID 和规格，避免预览与大图混用。

## 列表

沿用默认每页 12 条的游标接口。`CustomScrollView + SliverList` 替代整页 Column，构建视口及邻近缓存区的卡片，离屏卡片可回收。距离底部约 600 逻辑像素时请求下一页；同一时刻只允许一个加载操作。失败保留当前内容、停止自动重试，显示手动重试入口。结束游标不再继续请求。已有筛选、城市、去重及过期请求保护继续生效。
