## 设计对照

依据已确认的 `all-places-list-map.html`，对照 Flutter 实际渲染截图检查列表、选点地图、票种详情、无价格状态、折页式游玩准备入口，以及原首页。截图保存在 `mobile/test/goldens/explore-*.png`；列表与选点地图的照片示例另见 `v6-map-390.png` 和 `explore-selected-real-390.png`。

- 保留首页大图、排版和随行入口，仅将原地图入口改为“全部景点”。首页像素差异局限于入口文字。
- 列表默认打开，搜索、分类、区域和排序在地图与列表间共享；选择地点切到地图并居中，地图下方显示简要介绍和详情入口。
- 所有城市共用缩放、拖动和圆形聚合标记实现，不按深圳特判。测试包括五个现有城市和一个新增城市标识。
- 列表每批渲染 20 条，接近底部加载下一批。分页针对已获取的公开景点目录，不是新增服务器分页接口；地图仍使用全量轻量目录。图片延迟构建、限制解码尺寸并使用 Flutter 内存缓存，支持加载失败重试。
- 票种和票种详情在 App 内展示，只有“前往购买”打开渠道；返回保留票种页面，不把浏览行为标记成付款。320 / 390 宽度均检查无溢出。
- 去掉选票与全部景点页面的随行按钮、票据上传/查看入口，以及随行页重复的行走设置；设置页保留原功能。历史票据文件不会因升级被清除，用户主动删除对应准备时仍清理。

设计示例中的景点、价格、距离不作为线上事实写入客户端。截图测试覆盖布局与操作；尚未用真机完成真实购票支付，不宣称不同渲染引擎、内容和字体下逐像素相同。

## CMS 与线上内容

CMS 购票配置新增自动解析、预览和人工编辑票种。通用解析支持公开 JSON-LD 商品/活动报价和具有明确票种、价格表头的表格，不依赖按景点定制适配器。HTTPS 请求限制响应大小、重定向次数，并拒绝私有网络地址。

需要登录、小程序、动态脚本加载的票种不能可靠解析时，保留已配置购票入口；不虚构价格、库存或支付结果。参考价格在客户端过期后隐藏，仍可进入渠道查看。自动解析发生于保存新链接/空票种配置或主动点击解析，不是定时刷新库存。

线上已回读确认六处收费景点的入口，详见 `ticket-channels-2026-10-11.json`。世界之窗、欢乐谷、仙湖植物园、野生动物园、锦绣中华主要是官方购票指引或小程序入口；东部华侨城配置明确标注的去哪儿项目票页，不冒充官方。免费景点没有改成收费。入口可用不代表六处都支持网页内直接支付。

## 部署

本次不改主 API 与数据库结构，无需部署主 API 或执行迁移。CMS 新解析接口及编辑器需要更新 CMS 服务后生效；已保存的六个景点入口是线上内容修改，与部署相互独立。

以下仅适用于确认使用仓库 Docker Compose 的服务器；先将 `DEEPTRAVEL_ADMIN_DIR`、`DEEPTRAVEL_ADMIN_BRANCH` 设置为该服务器已核实的 CMS 检出目录和分支。本次 CMS 推送分支为 `main`。不假设新服务器沿用旧目录或 SSH 地址。

```sh
cd "${DEEPTRAVEL_ADMIN_DIR:?Set the verified server CMS checkout}"
test "$(git branch --show-current)" = "${DEEPTRAVEL_ADMIN_BRANCH:?Set the verified CMS branch}" || exit 1
git fetch origin "$DEEPTRAVEL_ADMIN_BRANCH"
git pull --ff-only origin "$DEEPTRAVEL_ADMIN_BRANCH"
docker compose up -d --build admin-api admin-web
docker compose ps
```

无新增环境变量。本次按“实现完推送就行”的要求交付源码，没有部署服务器或重新打包 APK。
