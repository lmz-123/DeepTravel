## Why

见地已经具备独立地理围栏、乱序真实定位触发、旅程恢复和可选照片的部分能力，但旅程页仍主要用“下一条线索”和锁定节点表达进度，容易让用户误以为必须按路线顺序行走。需求三需要把正式现场体验统一为“空间上自由、故事上有序、进度上可恢复”，让推荐顺序只服务于理解，不再成为真实定位触发或完成阻塞。

## What Changes

- 将正式现场旅程的默认交互明确为自由漫游：当前真实位置同时评估全部尚未触发的已发布故事点，不使用路线位置或故事依赖筛选候选点；多个点同时满足时只选择距离最近者并继续幂等处理其他点。
- 继续使用每个故事点已有的独立触发区域、精度、稳定采样和冷却策略，不新增路线级统一半径、强制导航、城市范围或连续位置轨迹。
- 明确服务端真实定位触发不检查前置故事依赖；`dependency_ids`/因果模型只决定最终故事的作者顺序和重构内容，不决定用户的空间行走顺序。
- 保留旅程页原有节点轨道和节点选择入口，不用新的附近列表替换它。点击节点后，在节点轨道下方、音频播放卡片上方展示该节点对应故事点的后台文案、主题、预计时长、是否已听过及当前触发状态；没有可用位置时仍保留节点与后台参考顺序，但不显示虚假距离。
- 节点轨道完全按后台返回的实际节点数量渲染，不假定每个景区固定五个节点；根据节点密集程度自适应节点视觉尺寸和间距，超出安全点击密度时保留横向滚动能力。
- 允许用户先选择并前往任意故事点、跳过后再回来；选择未触发节点只查看信息和到达提示，不伪造触发、解锁或播放。已触发或已收集节点可继续打开、查看文字稿和回听，回听不回退或伪造现场进度。
- 保持中途退出后的服务端旅程状态、本地待同步事件和可选现场记录可恢复；部分漫游也进入已有旅程资料库/足迹，不要求完成全部节点或最终重构。
- 保持照片为可选留念、观察提示为非答题内容；二者都不成为触发、收集、恢复或重构资格的前置条件。

### Non-goals

- 不实现地图导航、转向提示、路径规划、路线优化、偏航提醒或强制“下一站”。
- 不新增城市/景区边界、路线级定位范围、定位轨迹、热力图或后台城市坐标识别。
- 不修改首页的景点距离排序，不推荐路线，也不重排路线详情或故事因果模型。
- 不新增答题、考试、强制观察反馈、强制拍照或图片正确性识别。
- 不重做现有音频生成、内容审核、私有照片存储、足迹真相源或重构交互。

### MVP validation goals

- 真实定位下先进入任意已发布故事点的独立触发范围都能触发，不会因推荐位置、前置故事或跳过其他点而被拒绝。
- 旅程页保留原节点轨道，全部节点可选择；节点下方先呈现所选节点的后台故事点文案与状态，再呈现音频卡片。节点数量可变且布局不溢出；用户无需持续看地图，也不会只看到“下一站”。
- 用户离开并重新进入后，已触发、已听、可选照片和待继续节点保持一致，部分旅程仍可从足迹访问。
- 收集顺序与实际步行顺序可以不同；最终重构项目和正确关系始终来自后台因果模型。
- 自动化测试证明未发布点不可触发、照片/提示不阻塞、无位置时不显示虚假距离，并覆盖真实定位乱序触发和恢复。

## Capabilities

### New Capabilities

- `free-roam-location-experience`: 定义正式现场自由漫游、独立故事点触发、附近点状态，以及空间顺序与故事因果顺序分离。

### Modified Capabilities

- `guided-journey`: 将碎片旅程的现场触发从前置依赖/当前位置推进调整为任意已发布点可触发，并明确部分旅程恢复、足迹保留与因果重构语义。
- `experience-client`: 在保留原节点轨道与节点页的前提下解除空间顺序限制，增加乱序节点选择、状态查看、回听和无位置回退，不用新列表替换原节点入口。

## Impact

- `backend/`: 调整碎片触发资格、公开旅程/足迹投影和相关测试；优先复用现有 journey、journey_fragment、trigger_region、story dependency 和 reconstruction 表，不预设新增迁移。
- `mobile/`: 调整真实定位候选状态、附近点派生模型、旅程页面、节点导航/回听及恢复测试；继续复用现有单一播放器、Riverpod 状态、定位流和本地 outbox。
- `/Users/li/Downloads/Project/Travel-Admin`: 现有后台已经支持逐故事点触发区域与发布状态，本次默认不改独立后台；只有实现核查发现无法表达所需字段时才提出独立变更，不在客户端硬编码点位。
- API compatibility: 保留现有触发、ledger、journey context、evidence 和 reconstruction URL；允许在响应中增加附近展示所需的非破坏性字段，旧客户端继续按既有字段工作。
- Privacy/runtime: 不新增坐标上传频率或位置留存；实时距离只在客户端内存计算，服务端仅按单次触发请求验证并继续丢弃原始坐标。
