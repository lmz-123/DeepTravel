## Why

见地的节点目前只有官方叙事和旅行者自己的私密留念，缺少“同一地点、同一问题”下来自其他旅行者的真实补充。将“见地现场”直接放在节点内容末尾，可以在不打断导览主线、不把产品改造成泛社区的前提下，让机位、经验、事实补充和现场观察持续沉淀。

## What Changes

- 新增绑定故事节点的“见地现场”动态：已认证旅行者可在自己已解锁的节点下浏览、发布、删除自己的动态，并按“机位、经验、事实补充、现场”分类；动态支持可选短标题与正文。
- 新增动态图片能力：允许从设备选择图片，或将既有私密足迹照片通过明确的二次确认复制为独立的社区可见媒体；私密 evidence 原件不会因发布、删除或过期而改变。
- 新增轻量互动与详情：旅行者可点赞/取消点赞、发表和删除自己的一级评论，并可举报不当内容；节点底部使用图片型或文字型摘要卡片展示标题/文字以及点赞、评论数量，点击卡片在当前节点上下文打开详情，查看完整内容、点赞旅行者和评论。
- 在行走页当前所选节点的全部官方内容、照片任务、进度操作之后，将“见地现场”作为页面最下方的内联区块；切换已解锁节点时动态内容随 `fragment_id` 切换，音频继续遵循现有全局播放规则。
- 在足迹详情中按已通关节点查看相同的“见地现场”内容，并可查看自己当时的照片、选择是否公开分享；主页、主页侧栏和路线发现页不增加动态入口。
- 收紧旅程页的信息密度：移除路线详情和旅程页的独立音色选择卡片，将音色入口收进音频播放卡片的图标；移除路线详情和旅程状态卡中重复的模拟定位开关，以设置页作为唯一模式开关来源，同时保留当前模式提示与模拟模式下的测试推进能力。
- 服务端新增节点动态、公开媒体、点赞、评论和举报的持久化/API，实施用户隔离、软删除、内容长度/媒体类型约束、幂等发布和基础举报隐藏策略。
- 增加后端与 Flutter 的领域模型、仓储、状态管理、错误/空态/分页状态、可访问性语义和覆盖关键权限边界的测试。

### Non-goals

- 不建设独立社区首页、主页菜单入口、关注关系、私信、用户主页、热门榜单或跨景点推荐流；动态详情是从节点卡片打开的上下文面板，不构成新的全局动态入口。
- 不允许旅行者动态替代官方导览文案、自动触发音频或被标记为官方史实；“事实补充”始终显示旅行者内容提示。
- 不自动公开私密足迹照片，也不复用有认证访问和保留期限的 evidence 对象作为公共图片 URL。
- 首版不做多层评论树、视频发布、编辑历史、后台人工审核工作台或复杂推荐算法。

### MVP validation goals

- 两个不同账号在同一已解锁节点能够看到一致的可见动态，并正确完成发布、分页、摘要卡片、详情、点赞旅行者列表、一级评论、举报和作者删除流程。
- 未解锁该节点或未登录的请求不能通过 API 获取或发布节点动态；另一个账号不能删除作者内容或读取其私密 evidence。
- 行走页和已完成足迹都能在节点内容最下方加载同一动态流，主页及侧栏没有动态入口，切换节点和播放音频不会产生跨节点内容或音频所有权错误。
- 私密照片只有经过显式“分享到见地现场”确认后才生成公开副本；删除动态不删除私密原图，私密原图过期也不破坏已发布的公开副本。
- 行走页与路线详情不再出现独立音色卡片或模拟定位开关；音色图标能够从当前播放卡片切换同一节点的音轨，设置页切换定位模式后导览状态能够同步。

## Capabilities

### New Capabilities

- `node-community`: 定义按节点访问的旅行者动态、社区图片、摘要与详情、点赞旅行者、一级评论、举报、软删除、分页、权限与隐私边界。

### Modified Capabilities

- `experience-client`: 将“见地现场”内联到行走页所选节点及足迹节点的最下方，定义摘要卡片与上下文详情交互，收拢音色和模拟定位控件，同时明确主页和主页菜单不提供动态入口。

## Impact

- `backend/`: 新增 Alembic 迁移、SQLAlchemy 模型、节点动态应用服务、媒体存储边界、REST 路由、序列化和权限/幂等/分页测试。
- `mobile/`: 新增动态领域模型与仓储接口、Dio API、Riverpod 列表/详情/互动状态、节点底部摘要卡片、动态详情、发布/评论/图片确认流程，并调整音频卡片、路线详情、旅程状态卡和足迹详情。
- API: 新增 `/api/v1/journeys/<journey_id>/fragments/<fragment_id>/community-posts`、动态详情、点赞旅行者分页，以及发布、点赞、评论、举报和作者删除子资源；旅程上下文用于校验节点已解锁，所有创建型写入要求认证和幂等键。
- Storage: 新增与私密 evidence 隔离的“社区可见”媒体命名空间；继续复用现有本地/OSS 适配思路，但使用独立对象、授权读取地址与生命周期，不把对象暴露为无需登录的公共资产。
- 运行与发布: 需要数据库迁移、API 重建部署和新的 Android 生产 APK；不修改 `Travel-Admin` 独立仓库。
