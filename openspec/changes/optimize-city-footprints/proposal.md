## Why

当前“足迹”仍以路线完成统计、旅程账本和音频回听为中心，无法清楚保存用户在单个故事点获得的城市理解、现场观察与私人记忆，也会让历史记录受到旁白版本变化影响。需求三已经允许部分漫游和任意顺序触发，现在需要把每次故事触发沉淀为可稍后整理、长期可读且默认私密的城市足迹。

## What Changes

- 保留全局入口名称“足迹”，在首页增加服务端驱动的“继续我的足迹”入口，优先回到最近一条待整理的私人足迹，而不冒充路线继续入口。
- 每个故事点首次触发时幂等创建一条用户私有足迹草稿；用户可以立即或稍后选择后台提供的短总结、填写“我看到的”细节和“我留下的”短句，并上传至多一张私人照片，所有补充项均可跳过。
- 新增与旅程播放状态分离的足迹快照模型，保存城市、场景/故事点、故事标题、审核后的编辑摘要、用户选中总结、观察、短句、主题和时间；历史展示不读取音频 URL、播放进度、声音配置、供应商或当前内容版本。
- 将足迹详情重构为“见地讲述 / 我看到的 / 我留下的”三段式记录，移除路线统计主叙事、播放器、回听、播放进度、声音版本及足迹内社区流；未完成漫游只作为可返回正式旅程的独立状态，不污染足迹内容卡。
- 支持按城市、主题和时间筛选/排序足迹，展示未完成漫游，并依据城市或主题推荐其他已发布城市文字内容；空态、离线、旧内容撤回和无照片状态均保持可读。
- 生成本地可分享的足迹卡；默认只使用概括性文字，只有用户主动勾选照片并确认系统分享操作时才把私人照片写入本次导出副本，不自动创建公开社区内容。
- 后台内容模型、手动编辑和 JSON 导入增加审核摘要、可选短总结及足迹主题配置；客户端不硬编码城市、故事点、总结或主题。
- 为现有已触发/已完成旅程提供幂等历史足迹回填，保留旧路线的概括性内容和私人照片访问，不把旧播放字段复制进新足迹。

### Non-goals

- 不新增长篇游记编辑器、社交动态入口、自动公开分享、公共足迹排行榜、地图轨迹、城市坐标识别、路线推荐或答题任务。
- 不在足迹内保留或重新实现语音播放器、回听入口、播放进度、声音选择、音频版本或供应商字段。
- 不改变正式旅程中的定位触发、附近点排序、音频播放和故事因果重构规则。
- 不复用有保留期的现场证据照片作为长期足迹照片的唯一存储；也不因用户跳过整理、文字或照片而阻塞旅程。

### MVP Validation Goals

- 完成任意一个故事点后即可看到并整理对应足迹，退出后可从首页或足迹页继续。
- 足迹 API 和页面在更换旁白音频、声音配置或供应商后保持相同内容，并且契约中不存在播放字段。
- 用户可以按服务端城市、任意主题和时间找到记录，查看部分漫游状态与相关城市文章。
- 私人照片不会出现在公共 URL、社区或分享卡中，除非用户对当次导出作出明确选择和确认。

## Capabilities

### New Capabilities

- `traveler-footprints`: 覆盖单故事点足迹草稿、审核内容快照、短记录、长期私人照片、浏览筛选、部分漫游关联、相关城市文字和主动分享卡隐私边界。

### Modified Capabilities

- `guided-journey`: 在故事点首次正式触发或旧旅程回填时幂等建立与播放状态解耦的用户足迹草稿，且整理行为不阻塞漫游。
- `route-discovery`: 首页为当前用户展示最近待整理足迹的继续入口，并保持城市、主题及关联内容全部由服务端提供。

## Impact

- `backend/`: 新增足迹记录与长期私人照片持久化、迁移、所有者隔离服务及 REST API；扩展故事内容投影和历史回填，不改变现有旅程/音频接口。
- `mobile/`: 新增足迹领域模型、仓库与编辑/筛选/分享卡状态；重构足迹列表和详情，增加首页继续入口，并确保足迹模块不依赖活动播放器。
- `Travel-Admin/`: 独立提交故事点足迹摘要、短总结选项和主题的手动编辑、JSON 校验/导入与审核发布支持。
- 内容与隐私：足迹保存已审核文字快照和用户私有数据；分享只生成用户主动导出的本地副本，现有社区发布仍是另一个显式流程。
- 兼容性：新增 API 与可选内容字段向后兼容；部署顺序为数据库/API与后台先行、内容发布、客户端后行，并为旧旅程执行幂等回填。
